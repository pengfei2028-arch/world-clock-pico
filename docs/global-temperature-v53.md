# 全球气温 V53 / 0.53.0

## 当前交付

沿用原生 Kotlin / Compose / PICO Spatial SDK 6.1.9 工程，保持 StageStyle.Mixed、前方黑色区域及身后 VST。没有创建 Unity 工程，没有扩展新闻、风、降水或 Shared Space。

在世界时间与全球气温间切换；保留地球的位置、尺寸、展示朝向和城市列表，不重播开场。各模式保留自己的时间状态。气温模式沿用旋转、选城、时间操作暂停以及松手 3 秒、选城 5 秒、至少 4 秒回正的规则。世界时间的原材质、太阳时刻、静态云层、城市天气功能在返回时恢复。

## 使用

1. Full Space 开场完成后，在地球左上方选择“全球气温”。
2. 拖动下方时间轴，逐小时切换已下载的实际有效时刻；蓝点是数据范围内最接近现在的预报时次，白条是选定时次。日期、时区及数据有效时间显示在图例上方。
3. “现在 · 最近预报时次”选择最接近系统实际时间的已加载模型时次，不伪造未加载时刻。
4. 通过左侧 + 城市菜单选择城市；卡片数值来自正在显示的同一 GFS 全球网格，在城市经纬度作双线性采样，精确到显示小数一位。它是网格预报，不是本地实测。
5. 图例右侧拖动叠加强度，初值 55%，范围 0–100%。强度不改变数值与色阶。
6. 右侧更多显示起报时间、有效时间、服务端获取时间、设备取得时间；可前/后一小时或检查更新。技术时间戳以 UTC 的 Z 标记显示。
7. 返回“世界时间”恢复此前的实时时间或时间预览状态。未选择城市时仍按原规则自转。

切换入口、时间轴、图例的位置与尺寸，以及颜色、边界柔化、亮度均为本项目的视觉选择；UI 沿用官方 PICO 玻璃材质、系统字体和 Highlight。

## 真实数据样例

- NOAA GFS 0.25°，变量 TMP，层级 2 m above ground。陆地、海洋全部是近地面空气温度，不使用海水温度。
- 内置起报：2026-10-22 00:00 UTC。
- 内置有效范围：2026-10-22 07:00 至 2026-10-23 08:00 UTC，共 26 帧。这是当前附近到未来至少 24 小时的样例，之后不会自行被标为最新。
- 每帧完整 1440 × 721 全球数值网格；显示纹理 1442 × 723 含边界保护像素。提高显示分辨率不提高 0.25° 的气象精度。
- 内置数据总量约 59 MB。确切获取时间、URL、原 GRIB SHA-256、资源大小、资源 SHA-256、温度范围及缺失数量均在 app/src/main/assets/temperature/manifest.json。
- 自动更新未配置时明确显示“内置真实样例 · 自动更新待配置”。起报超过 18 小时或实际时间超出最后有效时刻时标记过期；18 小时是本项目保守策略，不是 NOAA 官方时效承诺。

NOAA 官方产品说明列出 00/06/12/18 UTC 周期，0.25° 逐小时输出覆盖最初 120 小时。产品目录同时列出部分旧接口，因此本实现实际使用已验证的 HTTPS GRIB Filter，而不依赖旧 OPeNDAP：

- https://www.nco.ncep.noaa.gov/pmb/products/gfs/nomads/
- https://nomads.ncep.noaa.gov/
- https://www.nco.ncep.noaa.gov/pmb/products/gfs/gfs.t00z.pgrb2.0p25.f000.shtml
- https://www.weather.gov/disclaimer

原始 TMP 单位是 K，处理时减 273.15 转为 °C。预测时次称“气温预报”，若单独载入 f000 则称“模型分析”；逐小时切换模型时次不等于每小时新增全球实测。NOAA/NWS 页面数据通常为公共领域，仍须遵守该来源列明的例外、标注来源，不暗示 NOAA 背书，转换后的视觉不冒充官方发布图；网络发布及时性不保证。没有引入第三方收费云图。

## 数据与材质

温度与颜色分离。查询文件 .wctz 是 gzip 封装的 WCT1 + little-endian uint32 宽高 + int16 摄氏温度乘 100；-32768 是缺失。使用 .wctz 扩展名，避免 Android 打包器把 .gz 自动解包、改名而破坏校验。

PNG 为数值 RGB8、RAW + LINEAR、不生成 mipmap、不作有损纹理压缩：归一化采样后 C = R × 652.8 + G × 2.55 − 100，B 表示有效性。色阶固定于 −30、−20、−10、0、10、20、30、40 °C，端点延伸至更冷/更热区域，缺失为独立灰色。每个边界仅 0.9 °C 柔化；不按每小时极值归一化。第一版没有时间插值，选择真实整数小时帧。

原 GRIB 经度 0…359.75 转成 −180…179.75；wgrib2 默认 WE:SN 解码后翻转成北到南。贴图左右各加一列经度回绕像素，上下各重复极点一行。模型新增地理 UV1，根据现有 GlobeGeography 的格林尼治方位 198° 与 Z 轴极点从原几何位置计算；跨日期线三角作展开，极点按相邻顶点处理。原 UV0 留给 8K 底图与法线。

气温材质引用原 8K Day / Normal GPU 资源，不复制或降低底图分辨率。气温模式降低底图饱和度、保留明度细节和法线，减弱镜面与昼夜差异，云层按现有渐隐机制隐藏。补光仅服务于气温可读性，不用于更改世界时间的真实太阳算法。两个材质、两个网格通过 SDK toGlobal 保留，避免解绑时自动释放原材质；旧气温纹理在替换完成后及时释放。

## 性能与失败处理

下载、哈希校验、网格解压、纹理准备放在 IO 协程；滑动有 70 ms 合并请求，取消过时加载。显示纹理、城市查询网格与有效时刻在同一次场景更新提交，准备期间保留上一帧并显示切换状态。单帧约 2 MB CPU 数值，RGBA GPU 约 4 MB；额外原网格副本约 1.4 MB。实际底图、SDK 开销另计。

客户端下载一个完整不可变小时包，逐文件校验尺寸和 SHA-256，同周期窗口前移时复用校验一致的缓存帧，仅下载变化资源；全部成功后原子切换 current.txt。失败不切换，缓存重启先验证，损坏时回退内置真实样例。磁盘保留样例、当前和上一数据包；GPU 仅保留当前、待提交及极短暂退休帧。发布端保持至少 48 小时包以支持正在下载的客户端。
