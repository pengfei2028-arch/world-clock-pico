# 全球气温 V54：独立球壳与流畅色带

本轮按用户概念图和最新反馈修正 V53 视觉。原生 Kotlin / Compose / PICO Spatial SDK 6.1.9；V53 提交 ee6626a 可回退。

## 本轮变化

- 独立 TemperatureShell_V54 实体、网格、材质和数值纹理，半径为原地球的 1.003 倍；挂在原地表实体下，同步所有地球旋转和开场层级。原地球网格与材质不再替换。
- 默认覆盖不透明度 80%，调节范围 0–100%。SDK OpacityController 控制真实透明合成；不是把 80% 写进原地球颜色混合节点。仅渲染球壳正面、深度测试开启、深度写入关闭。
- 色彩以用户“全球气温叠加地球界面(1).png”概念图为参考，恢复鲜明蓝、青、浅青、浅黄、橙、红、深红。固定每 5°C 一档，共 16 档，图例每 10°C 标字。小于 −30°C、大于等于 40°C 及缺失值各有明确表示；不随帧调整极值。
- 使用 SDK 自带 ND__unlit_surfaceshader，避免 PBR 发光通道受场景曝光影响而把橙色压成褐色。颜色转换遵循 sRGB / linear 路径，不增加发光光晕。
- 显示温度先作三次半径 2 网格的归一化箱式卷积，约等效 0.61° 的高斯平滑；映射到固定色阶时，边界仅 0.44°C 柔化。连续等温轮廓呈矢量风格，仍是由真实数据生成的数值贴图，不是手绘矢量地图。
- 保留原始网格供城市查询，不修改下载数据。海陆均为 GFS 2 m 空气温度。显示平滑不是提高气象精度，局部尖峰及山地细节会被简化，城市卡片仍显示原始网格双线性采样值；更多面板说明这一点。
- 球壳引用现有 8K 昼图与海陆遮罩，只提取无色的地形明暗；轻微视角边缘明暗保留球体体积，不借用太阳昼夜改变温度色阶。原图无重采样和降分辨率。
- 只在气温叠加时按强度减弱原地表反射，防白色太阳高光洗掉气温。强度归零、返回世界时间或释放资源时恢复保存的反射参数。太阳、云层原有开场/交互规则保留。

## 数据与缓存

仍使用 V53 的 NOAA GFS 真实 26 小时样例，起报 2026-10-22 00Z，有效 07Z 至次日 08Z；没有把概念图色块充当气象数据。服务端清单的 legendBreaksC 保持 10°C 主刻度协议，客户端在其间细分固定 5°C 档。

显示平滑与 PNG 生成在 IO 协程执行。数值采用原有 RGB 编码、RAW + LINEAR、不生成 mipmap；原始数据包校验规则保留。经度周期卷积和边缘保护像素避免日期线接缝；南北端汇聚为统一极点值，原缺失格仍缺失。仅保留当前/待提交/短暂退休纹理，释放纹理时删除相应显示缓存文件。

验证结果见 validation/v54-validation.json。模拟器验证仅代表模拟器；头显佩戴色彩、视线/手势、帧率与长期运行仍待验收。V53 已记录的模拟器间歇截图截断问题不在本轮宣称解决的范围内。

## 文件与操作

- 运行工程：WorldClockSpatial；Git 副本同步同名目录。
- 材质生成：tools/generate_temperature_material.py；编辑器场景 TemperatureV54.usda，模型 TemperatureShellV54.usda。
- 启动 Full Space 后选择“全球气温”，默认 80%。调至 0% 可查看原地表，返回“世界时间”恢复原功能。
- APK：builds/WorldClock_v54_TemperatureShell.apk（工作区上级 builds 目录）。
- 公网数据服务与定时部署状态沿用 V53：尚未部署，不把内置样例宣称为自动更新。
